# Логи чатов Cursor в Dex

Логи ведутся **в vault (Dex)**, в git, а не в истории Cursor. Их можно открыть в другом чате, в Obsidian или поиском по репозиторию.

## Где лежат файлы

- Один файл на календарный день: `System/Chat_logs/YYYY-MM-DD.md`
- Запись **дописывается в конец** (append-only в пределах дня)
- Новый день = новый файл (старое не перезаписывается)

## Кто пишет

- **По умолчанию:** ассистент Cursor дописывает блок **после каждого завершённого своего ответа** по правилу `.cursor/rules/dex-chat-session-log.mdc`
- В блок попадает смысл **последнего запроса пользователя** и **что сделал ассистент** (включая правки файлов)

## Чего этим не закрыть без отдельной автоматизации

1. **Сообщение пользователя без следующего ответа ассистента** в этот же момент в файл не попадёт (ответа ещё не было, кто пишет лог)
2. **Пока ассистент не ответил**, очередное твоё сообщение не будет в логе как отдельная строка до следующего завершённого хода ассистента
3. Cursor **не отдаёт** репозиторию «сырой транскрипт чата» автоматически: дублирование идёт через то, что агент сам пишет в markdown

Если понадобится лог **каждого** сообщения без пропусков, следующий уровень — **Cursor Hooks** (скрипт на событие после сообщения) или ручная вставка в конец дневного файла. Текущая схема намеренно простая и не требует хуков.

## Конфиденциальность

- В лог могут попасть формулировки задач и пути к файлам
- При необходимости добавь `System/Chat_logs/*.md` в `.gitignore` локально или исключи папку из бэкапов в облако

## Как продолжить в новом чате

Скажи ассистенту: прочитай `System/Chat_logs/YYYY-MM-DD.md` (или последние N дней) и продолжи. Параллельно работает поиск по vault (qmd) по коллекции, если настроен.
