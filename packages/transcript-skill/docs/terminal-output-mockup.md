# Целевой вид вывода `transcript-media` (как в терминале, описано в MD)

Ниже зафиксирован **один** эталонный порядок блоков и плотность текста. Терминал должен повторять эту логику: те же поля, те же заголовки, без «шума» вроде длинных линий-разделителей на каждый абзац и без повторяющихся строк прогресса на одном и том же этапе.

---

## 1. Заголовок запуска (одна строка)

**transcript-media** · YouTube (аудио → Whisper) · `tiny` · compute `auto` → **`int8`** (MPS)

Смысл: сразу видно источник, режим, модель и **итоговый** compute без простыни «параметров».

---

## 2. Ввод (только факты, список)

- **URL или путь:** `https://www.youtube.com/watch?v=…`
- **Режим:** скачать аудио (yt-dlp) → локальный faster-whisper
- **Модель:** `tiny` (`Systran/faster-whisper-tiny`)
- **Язык:** авто (или явный код, если передан)
- **compute (запрос → факт):** `auto` → `int8` · причина одной строкой: MPS, авто-подстройка по RAM
- **Нарезка:** не используется (короткий файл) **или** `N` мин, если включена
- **VAD:** да/нет · **предобработка ffmpeg:** да/нет · **диаризация:** да/нет

Смысл: один блок «что решили», без дублирования с блоком плана ниже.

---

## 3. План работы (короткий, по шагам)

1. Скачать аудио (yt-dlp), при необходимости тихий лог загрузки **в одну строку** или с `--no-progress` для yt-dlp, чтобы не засорять экран.
2. ffprobe: длительность `Xs` (~`Y` мин).
3. Загрузка весов (при первом запуске может быть загрузка с Hugging Face).
4. Распознавание (Whisper).

Смысл: пользователь понимает **последовательность**, а не читает второй раз те же параметры под другим заголовком.

---

## 4. Прогресс (одна активная строка)

В терминале: **одна** строка, которая **обновляется на месте** (carriage return / Rich Progress), например:

`[transcript-media] load_model … | whisper 0% … 100% | done`

Запрещено в эталоне:

- пять строк подряд с `100.0% whisper` и `100.0% done`;
- смешивание прогресса yt-dlp (многострочный `[download]`) с прогрессом Whisper без разделения: либо подавить многострочный вывод yt-dlp, либо вывести одну строку «audio: ok» после скачивания.

Смысл: глаз цепляется за **одну** шкалу, а не за лавину процентов.

---

## 5. Результат

- **Статус:** OK / ошибка (код)
- **Язык распознанный:** `en`
- **Длительность медиа:** `19.0` с
- **Транскрипт (превью):** первые N символов или первый абзац
- **JSON:** одна строка в stdout **или** путь к файлу, если режим «только файл»

Смысл: человек читает превью в stderr/логе; машина забирает JSON из stdout без смешения с планом.

---

## 6. Чего не должно быть в «нормальном» выводе

- Повторяющихся заголовков **transcript-media** с одинаковой ролью (параметры / план / снова план).
- Строки-подсказки вроде «stderr, видно в терминале и в логе при 2>file + tee» в пользовательском лице.
- Пустых строк-«подпорок» между блоками только ради визуала (допустима одна пустая между крупными секциями).
- Дублирования «почему int8» в трёх местах: достаточно **один раз** в блоке ввода или в блоке плана, не в обоих развёрнуто.

---

## Пример «как должно читаться» (весь лог до JSON — условно 25–40 строк, не 80)

```text
transcript-media | YouTube→Whisper | tiny | auto→int8 (MPS)

  url:     https://…
  audio:   yt-dlp → /tmp/…/source.mp3
  model:   Systran/faster-whisper-tiny
  lang:    auto → en
  chunks:  none (0.32 min < 10 min threshold)
  vad:     on

  steps:  download → probe (19 s) → load_model → transcribe → done

  [=========>                    ] load_model
  [============================>] whisper
  done in 8.2s

  preview: Alright, so here we are…

{"ok":true,"schema_version":"4",...}
```

(В реальном терминале полоса `[====]` — одна строка с обновлением, не тридцать строк процентов.)

---

## Связь с кодом

После согласования этого MD:

1. Привести вывод CLI к секциям **1–5** (текст/ Rich без лишних Panel).
2. Свести прогресс к **одной** дорожке + убрать дубли процентов на этапе whisper.
3. Подавить или сузить вывод yt-dlp до одной строки «готово».

До этого **не** запускать демо-транскрибацию для «проверки красоты».
