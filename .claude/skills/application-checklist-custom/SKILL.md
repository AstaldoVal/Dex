# Application Checklist — Pre-Response Verification

**Command:** `/application-checklist-custom`

Проверяет резюме и сопроводительное письмо перед откликом на продуктовую вакансию по чек-листу GoPractice (4 марта 2026). Помогает не «потратить» шанс на первое впечатление.

## When to Use

- **Перед откликом** — когда резюме и/или cover letter готовы и нужно свериться с критериями.
- **После `/job-apply`, `/job-summary` или `/cover-letter`** — быстрая проверка перед отправкой.
- **С подозрением на слабые места** — фокус на пунктах, отмеченных ⚠️.

## Inputs (Use Automatically)

| Input | Source |
|-------|--------|
| **Резюме** | `CV Examples/Roman Matsukatov - CV.md` (или PDF, если MD отсутствует). Либо резюме/Teal Professional Summary из сообщения пользователя. |
| **Сопроводительное письмо** | Файл из `00-Inbox/Job_Search/cover_letters/` (последний или указанный) или текст из сообщения. |
| **Описание вакансии** | Сообщение пользователя или вложение (для проверки соответствия позиции и компании). |

Если чего-то нет — спросить один раз: «Пришлите описание вакансии / путь к cover letter, чтобы проверить соответствие».

## Checklist (GoPractice, 4 марта 2026)

Читать полный чек-лист: `.claude/skills/application-checklist-custom/references/checklist.md`.

### Резюме (8 пунктов)

1. Отражен релевантный опыт и достижения
2. Опыт представлен через результаты, а не процессы ⚠️
3. Упомянуты нерабочие проекты, связанные с профессией
4. Названы ключевые хард- и софт-скиллы
5. Указано основное и дополнительное образование
6. Заточено под конкретного работодателя и позицию ⚠️
7. Одностраничный документ
8. Оформлено аккуратно, ошибок нет

### Сопроводительное письмо (5 пунктов)

1. Сказано, почему интересна именно эта компания и эта позиция ⚠️
2. Сказано, почему вы подходите лучше всего, показана мотивация ⚠️
3. Коротко упомянуты релевантные достижения
4. Одностраничный документ
5. Оформлено аккуратно, ошибок нет

## Process (Run in Order)

1. **Получить материалы.** Резюме (CV или Teal summary), cover letter (файл или текст), JD (по возможности).
2. **Прочитать чек-лист** из `references/checklist.md`.
3. **Проверить резюме** по каждому из 8 пунктов. Для каждого:
   - ✅ Pass — явное соответствие
   - ⚠️ Attention — частичное соответствие или сомнение
   - ❌ Fail — явное несоответствие
   - N/A — неприменимо (напр. нет нерабочих проектов)
4. **Проверить cover letter** по каждому из 5 пунктов. Аналогично Pass / Attention / Fail / N/A.
5. **Выдать отчёт:**
   - Краткая сводка: сколько ✅ / ⚠️ / ❌ по резюме и по письму
   - Детали по каждому Fail и Attention
   - Конкретные рекомендации по исправлению (1–2 предложения на пункт)
   - Приоритет: сначала пункты с ⚠️, затем Fail

## Output Format

```markdown
## Application Checklist — [Company / Role]

### Резюме: X/8 ✅, Y ⚠️, Z ❌
- [Детали по проблемным пунктам]
### Cover letter: X/5 ✅, Y ⚠️, Z ❌
- [Детали по проблемным пунктам]

### Рекомендации
1. [Первое приоритетное исправление]
2. [Второе]
...
```

## Rules

- **Не изобретать.** Оценивать только по факту: что есть в резюме и письме.
- **Без AI-языка в выводе.** Следовать `.claude/reference/ai-writing-signs-banned.md` в формулировках рекомендаций.
- **Критичные пункты (⚠️).** Если по ним Fail или Attention — явно указать: «Критично: …».
- **Ссылки на другие скиллы.** При необходимости направить: `/job-summary`, `/job-apply`, `/cover-letter` для доработки.
