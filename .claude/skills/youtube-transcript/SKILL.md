## Purpose

Получить текст транскрипта из YouTube, Apple Podcasts URL или локального видео/аудио файла и структурированное саммари: ключевые темы, основные мысли, опорные моменты с привязкой ко времени (если есть сегменты). Удобно для конспектов лекций, подкастов, докладов без необходимости смотреть материал полностью.

## Usage

- `/youtube-transcript` — затем ввести URL YouTube / Apple Podcasts или путь к локальному файлу.
- Можно сразу вызвать с URL: `/youtube-transcript https://www.youtube.com/watch?v=...`
- Можно сразу вызвать с Apple Podcasts URL: `/youtube-transcript https://podcasts.apple.com/...`
- Можно сразу вызвать с локальным файлом: `/youtube-transcript /Users/.../video.mp4`

## Dependency

Standalone-пакет использует:

- **youtube-transcript-api** — субтитры YouTube без API-ключа.
- **faster-whisper** — локальная транскрибация видео/аудио.
- **yt-dlp** — загрузка аудио для Apple Podcasts URL.
- **ffmpeg** — системная зависимость для чтения медиа.

**Однократная установка:**

```bash
pip install -r packages/transcript-skill/requirements.txt
```

или пакет в editable-режиме (команда **`transcript-media`** в PATH):

```bash
pip install -e packages/transcript-skill
```

или отдельно:

```bash
pip install youtube-transcript-api faster-whisper yt-dlp
```

Проверка ffmpeg:

```bash
ffmpeg -version
```

Если скрипт завершается с ошибкой «Missing dependency», предложить установку недостающей зависимости.

### Веса Whisper (не в репозитории)

Чекпоинты **Whisper не лежат** в репозитории и **не** входят в папку скилла. Они **скачиваются отдельно** в кэш Hugging Face (часто `~/.cache/huggingface/hub`). Для качества выше, чем у `small`, для **локальных файлов** и **Apple Podcasts** можно использовать **`--model large-v3`** (порядка **~3 GB** на диск для весов).

Предзагрузка **Large v3** (удобно до офлайн-работы):

```bash
download-whisper-weights large-v3
# или: python3 packages/transcript-skill/scripts/download_whisper_weights.py large-v3
```

Без предзагрузки при **первом** запуске с `--model large-v3` веса скачаются сами (нужен интернет один раз).

**Прогресс в терминале.** Команды **`download-whisper-weights`** / **`download_whisper_weights.py`** **не показывают** полосы прогресса: в **`faster_whisper.utils.download_model`** в Hugging Face **`snapshot_download`** передаётся **`tqdm_class=disabled_tqdm`**. Чтобы **видеть прогресс** при скачивании в тот же кэш Hub (`~/.cache/huggingface/hub`, модель **`Systran/faster-whisper-large-v3`**):

```bash
HF_HUB_DISABLE_PROGRESS_BARS=0 hf download Systran/faster-whisper-large-v3 --no-quiet
```

При необходимости принудительно перекачать: добавить **`--force-download`**. См. также **`AGENTS.md`** → Learned Workspace Facts (Whisper large-v3).

## Правила для агента (обязательно)

1. **Чей файл:** использовать **тот же** URL или путь, что дал пользователь. **Не** подменять вход синтетическим тихим аудио или другим файлом «для теста», если пользователь явно не просил проверку вывода на фиктивном образце.
2. **Список параметров в терминале:** при любом запуске `transcript-media` / `transcribe.py` скрипт **сам** печатает в **stderr** первым делом блок **«выбранные параметры»** (все флаги и вход). Агент **не** должен отключать или перенаправлять **stderr** в никуда: иначе пользователь не увидит таблицу параметров и прогресс. Если JSON пишется в файл (`> out.json`), stderr должен идти в лог и/или терминал (лучше **`packages/transcript-skill/scripts/transcribe_to_log.sh`**).
3. **Полоса прогресса Rich:** если пользователь хочет **обновляемый бар** (спиннер, процент, фаза), передавать **`--progress-format rich`** или оставить **`auto`** в настоящем интерактивном терминале. В среде без TTY полоса всё ещё может появиться через **`/dev/tty`**; при записи stderr в файл **`transcribe_to_log.sh`** даёт и **tee** в окно терминала, и накопление в `.log`.
4. **Явная команда в ответе:** когда агент запускает транскрибацию, в ответе пользователю привести **полную** команду с теми же флагами (**`--model`**, **`--diarize`**, **`--progress-format`**, путь к файлу), чтобы совпадало с тем, что реально выполнено.
5. **Диаризация и HF-токен:** перед запуском с **`--diarize`** убедиться, что задан **`HF_TOKEN`** или **`HUGGINGFACE_HUB_TOKEN`** (или будет передан **`--hf-token`**, значение в чат не копировать). Без токена **`transcript-media` завершится сразу** с ошибкой: полоса Rich до Whisper не дойдёт. Если токена нет в **`Dex/.env`**, не обещать «идёт транскрибация»: сообщить, что нужен токен и условия моделей pyannote на Hugging Face, затем **`pip install -e 'packages/transcript-skill[diarize]'`** при необходимости.

## Process

### Step 1: Получить источник (YouTube URL, Apple Podcasts URL или локальный файл)

- Если пользователь уже указал URL/путь в сообщении (например после `/youtube-transcript`) — использовать его.
- Поддерживаемые YouTube-форматы: `youtube.com/watch?v=ID`, `youtu.be/ID`, `youtube.com/embed/ID`.
- Поддерживаемые Apple Podcasts URL: `podcasts.apple.com/...`.
- Поддерживаемые локальные форматы: `.mp4`, `.mov`, `.mkv`, `.webm`, `.mp3`, `.m4a`, `.wav`, `.flac`, `.ogg`, `.opus` (и др. из скрипта).
- Если ничего не передано — запросить: «Пришли ссылку на YouTube или путь к локальному файлу».

### Step 2: Получить транскрипт

Запустить скрипт из корня репозитория:

```bash
python3 packages/transcript-skill/scripts/transcribe.py "URL_ИЛИ_ПУТЬ_К_ФАЙЛУ"
# или после pip install -e packages/transcript-skill:
transcript-media "URL_ИЛИ_ПУТЬ_К_ФАЙЛУ"
# для локальных файлов и подкастов, примеры:
# --model large-v3 --language ru --preprocess-audio --chunk-minutes 45
# --compute-type auto (по умолчанию), прогресс в stderr: --progress (по умолчанию)
# диаризация (интервью, встречи): pip install -e "packages/transcript-skill[diarize]" && export HF_TOKEN=...
# transcript-media --diarize "/path/to/meeting.m4a"
```

Скрипт выводит в **stdout** JSON (версия схемы в поле **`schema_version`**, сейчас **`"4"`**). **Процент выполнения** (если не **`--no-progress`**) идёт в **stderr**, чтобы не ломать парсинг JSON.

**Прогресс.** В TTY по умолчанию **`--progress-format auto`** — полоса **Rich** (спиннер, процент, фаза, время). Если stderr **не TTY** (pipe, `2> log`, захват агента) — построчный режим с прореживанием и heartbeat на паузах между сегментами. Явно: **`--progress-format lines`**, **`rewrite`** (одна строка с `\r`), **`rich`**. План в stderr — **Rich Panel/Table** (без Rich: прежний текст); отключить панели: **`TRANSCRIPT_NO_RICH=1`**. Перед загрузкой весов **`large-v3`** — отдельное сообщение о длительном шаге. **`--compute-type auto`:** для **CUDA** выбирается **float16**, для **Apple MPS и CPU** — **int8** (на MPS **float16** у faster-whisper часто не поддерживается; агент не должен подставлять float16 на Mac по умолчанию).

**Параметры до старта.** В **stderr** сначала план **CLI**, затем для **Whisper** — секции (источник, модель, язык, **compute_type**, нарезка, дополнительно). Для **субтитров YouTube без `--youtube-audio`** — отдельный блок. Перед **yt-dlp** — баннер конвейера; перед загрузкой весов — отдельная панель.

- **Успех (YouTube, по умолчанию):** субтитры с сайта (**не** Whisper), **`transcription_mode`:** `youtube_captions`, **`caption_language_code`**, **`video_id`**, **`transcript`**, **`segments`**. Разделения по людям **нет** (в субтитрах нет меток говорящих).
- **Успех (YouTube, Whisper по аудио):** передать **`--youtube-audio`** (скачать дорожку через yt-dlp и прогнать Whisper) **или** **`--diarize`** (диаризация сама требует аудио, путь переключается автоматически). В JSON **`transcription_mode`:** `youtube_audio_whisper`, **`youtube_audio_download`:** `true`, дальше как у локального Whisper (включая **`--diarize`** и поля по говорящим).
- **Успех (local / podcast):** **`transcription_mode`:** `whisper_local`, **`whisper_model`**, **`compute_type`** и разрешение **`compute_type_request` / resolution**, **`tuning`** при авто-подстройке, **`language_requested` / `language_used`**, **`quality_hints`**, при длинном файле **`chunk_minutes`** и **`chunk_minutes_resolution`**, **`transcript`**, **`segments`**. С **`--diarize`:** **`transcript_by_speaker`**, **`transcript_speaker_formatted`**, **`diarization_applied`:** `true`, в **`segments`** поле **`speaker`**. Локальный скачанный **`.mp4` / `.mkv`** обрабатываются так же: путь к файлу + **`--diarize`**.
- **Успех (local):** также **`source_path`**.
- **Успех (Apple Podcasts):** также **`source_url`**.
- **Ошибка (`ok: false`):** обычно тот же JSON в **stdout** (например нет субтитров). **Исключение** при разборе аргументов или падении процесса: JSON с ошибкой в **stderr**, exit code 1.

Если скрипт вернул `ok: false` — показать пользователю текст из `error` и не переходить к саммари. Типичные случаи: отключённые субтитры, приватное видео, отсутствие субтитров.

### Step 3: Сформировать саммари

По полю `transcript` (и при необходимости по `segments` для привязки ко времени) подготовить саммари на основе транскрипта. Если в JSON есть **`transcript_speaker_formatted`** или **`transcript_by_speaker`**, при выдаче пользователю **полного текста** или цитат опираться на них, чтобы реплики были привязаны к говорящим. Не придумывать содержание — только то, что явно есть в тексте.

**Структура саммари:**

1. **Краткое содержание (2–4 предложения)** — о чём видео в целом.
2. **Ключевые темы** — маркированный список основных тем/вопросов, которые обсуждаются.
3. **Опорные моменты** — важные тезисы, выводы, факты по порядку; при наличии `segments` указывать приблизительное время в формате «около N:MM» там, где это полезно.
4. **Что применить** (опционально) — если из видео следуют конкретные действия: что взять в работу, какие практики использовать, куда сохранить (например в референсы скилла). Явно формулировать action items, чтобы не перечитывать весь конспект.
5. **Язык транскрипта** — если очевидно (например только русский/английский), можно кратко указать.

Саммари выводить на том же языке, на котором в основном транскрипт (русский/английский/другой — по содержанию).

### Step 4: Выдать результат пользователю

Показать:

1. **Ссылку на видео** (по `video_id`: `https://www.youtube.com/watch?v={video_id}`).
2. **Саммари** в формате выше.
3. **Объём:** количество символов или слов транскрипта (по желанию).
4. По запросу пользователя — сохранить транскрипт и/или саммари в файл (например в `00-Inbox/` или `06-Resources/`) с именем вида `YYYY-MM-DD - YouTube - [название или video_id].md`. Название видео при сохранении можно взять из контекста или подставить `video_id`, если заголовок не получали. Если есть диаризация, в файл включать **`transcript_speaker_formatted`** (или структурированный **`transcript_by_speaker`**), а не только сплошной `transcript`.

### Step 5: Сохранение в файл (по желанию)

Если пользователь просит сохранить или скилл по умолчанию сохраняет результат:

- **Куда сохранять** (по смыслу): `00-Inbox/` — разовые заметки; `06-Resources/` по теме (например `06-Resources/Product/`); для материала под конкретный скилл — `.claude/skills/<skill>/references/` (как в linkedin-posting). Либо в указанную пользователем папку.
- Включить в файл: ссылку на видео, саммари (с блоком «Что применить», если был), при необходимости выдержки из транскрипта. Полный транскрипт — только если действительно нужен; предпочтительно саммари + выдержки + ссылка.
- Если видео относится к проекту или области — в заметке добавить ссылку на проект/область и кратко «что взять в работу».
- Имя файла: `YYYY-MM-DD - YouTube - <video_id или краткое название>.md`.

## Error Handling

- **Нет входа / неверный вход:** напомнить форматы YouTube URL и пример локального пути.
- **Скрипт не найден / Python ошибка:** проверить путь к `packages/transcript-skill/scripts/transcribe.py` и запуск из корня репозитория.
- **Missing dependency (Python):** предложить `pip install -r packages/transcript-skill/requirements.txt`.
- **Missing dependency (ffmpeg):** установить ffmpeg и проверить `ffmpeg -version`.
- **ok: false в выводе скрипта:** показать пользователю поле `error` без перехода к саммари (например «Субтитры отключены», «Нет доступного транскрипта»).

- **Исследование** — по каждому видео отдельное саммари, плюс один общий файл с выводами и ссылками.
