## Purpose

Помочь подготовить или проверить пост для LinkedIn на основе накопленных best practices и референс-материалов. Скилл опирается на папку `references/`: видео, статьи, чек-листы, фреймворки (например SLAY, работа с лидами). Референсы можно дополнять — скилл будет их учитывать.

## Usage

- `/linkedin-posting` — вызвать без контекста: показать актуальные best practices и чек-лист, предложить применить к черновику.
- `/linkedin-posting` + вставить черновик поста — проверить черновик по чек-листу и фреймворкам из референсов, дать конкретные правки.
- «Добавь в референсы LinkedIn» + ссылка/файл — предложить сохранить новый материал в `.claude/skills/linkedin-posting/references/` и кратко описать, что из него брать.

## Как вызывать скилл (шпаргалка)

Если пользователь забыл, как пользоваться скиллом — дать короткую подсказку по одному из вариантов:

- **Хочу напомнить себе практики** → вызови `/linkedin-posting` без текста: покажу чек-лист и практики из референсов.
- **Есть черновик поста** → напиши `/linkedin-posting` и вставь черновик в том же сообщении: проверю по чек-листу и SLAY, дам правки.
- **Нашёл полезное видео/статью** → напиши «Добавь в референсы LinkedIn» и ссылку: сохраню выжимку в папку references/.

Не требовать от пользователя помнить всё это: при неочевидном запросе («помоги с постом», «хочу написать в LinkedIn») предложить один из вариантов выше.

## Step 0: Load Trend Context (Silent)

Before helping write or review any post, check if fresh trend data exists:

1. Read `00-Inbox/LinkedIn_Trends/trends-context.json` (if it exists).
2. If `generatedAt` is within the last 14 days, silently use the top topics and formats as context.
3. Add a one-line note at the top of your response: **Trend context (Week YYYY-WW):** Top topic: [topic] — avg engagement [score]. Best format: [format].
4. If the file is missing or older than 14 days: skip silently. Offer to run `/linkedin-trends` if the user asks about what's performing well.

Do not interrupt the posting flow. This is background context, not a blocker.

## Mandatory rules for every LinkedIn post

При **генерации** текста поста и при **проверке** черновика всегда соблюдать:

1. **Цепляющий заголовок в начале.** В самом начале поста должна быть отдельная строка-заголовок (headline), которая цепляет внимание и задаёт тему. Не общее место, а конкретная мысль, парадокс или вопрос. Примеры: «I used to use AI only to do the same things faster.» / «Your experience is not the problem.» Заголовок может совпадать с первой строкой S (Story), но явно выделяется как «первое, что видит читатель».

2. **Теги (хэштеги) в конце поста.** После основного текста и вопроса/CTA всегда добавлять список релевантных хэштегов по теме поста (3–7 тегов). Подбирать под контент: тема поста, ниша, ICP. Пример: #AI #productivity #futureofwork #leadership #workflow

3. **Картинка при генерации поста (обязательно по умолчанию).** Когда генерируешь полный текст поста (а не только проверяешь чужой черновик), **сразу после выдачи текста** вызвать CLI-обёртку Nano Banana: `npm run nanobanana:generate -- --prompt "<english image prompt>" --image_size 16:9 --save_dir "00-Inbox/Generated_Images"`. Промпт — на основе темы и ключевой идеи поста (на английском). Скрипт выводит JSON, оттуда взять `saved_paths[0]` и выдать пользователю вместе с текстом поста. **Не пропускать** генерацию картинки, если пользователь не сказал явно: «только текст», «картинку сделаю сам», «без картинки», «text only». Исключения: команда недоступна или падает с ошибкой — тогда выдать только текст и **явно** показать готовую команду для ручного запуска, чтобы пользователь мог сам сгенерировать картинку.

4. **Промпт для картинки: смысл за секунду, не абстракция.** Обложка должна **с первого взгляда** отражать главный тезис поста (боль, контраст «до/после», метафора, одна ясная сцена). **Избегать** промптов вида «несколько абстрактных блоков / слоёв без истории»: в ленте это часто читается как «ничего». Предпочтительно: split-screen (хаос vs порядок), дорога/мост/фундамент, щит/замок для safety, аккуратный стек слоёв **в контексте** (например рядом с хаосом чатов). Сильный свет, контраст, редакционный стиль (как обложка журнала). Без текста на изображении. Если пользователь говорит, что картинка «ни о чём», **перегенерировать** с новым промптом по этим правилам, не ограничиваться повтором старой формулировки.

## Guidance: направляющие вопросы

Когда пользователь **пишет пост или прислал черновик**, не ограничиваться только вердиктом и правками. Если по референсам что-то не учтено или неясно — **задать 1–3 коротких вопроса**, чтобы пользователь сам дописал или уточнил. Цель: направлять, а не только судить готовый текст.

**Проверять по пунктам (если неочевидно из контекста — спросить):**

- **Тема и фокус:** Определена ли одна тема и 2–3 подпункта? Если пользователь ещё «просто хочет написать» — спросить: «Одна тема уже есть или подберём из референсов? О чём именно хочешь сказать в этом посте — educate / inspire / entertain?»
- **Цель поста:** Явно ли выбрана цель (educate / inspire / entertain)? Если нет — спросить: «Какую задачу ставишь: научить, вдохновить или развлечь?»
- **Заголовок:** Есть ли в самом начале поста цепляющий заголовок (одна строка, по возможности не выходящая за первый перенос строки; см. courtney-johnson-winning-posts.md)?
- **Триггер вовлечения:** Есть ли в конце вопрос читателю, просьба фидбека или выбор («два варианта»), чтобы провоцировать комментарии?
- **SLAY:** Есть ли в черновике все четыре блока (Story, Lesson, Actionable advice, You/PS)? Если чего-то нет — не только указать в правках, но и спросить: «Есть ли в начале короткая история/крючок? В конце — вопрос читателю или фраза “тебя услышали”?»
- **Хэштеги:** Добавлены ли в конце поста релевантные теги (3–7 хэштегов)?
- **Работа с комментариями (лиды):** Планирует ли пользователь после публикации смотреть комментарии и выходить на ICP? Если про лиды не говорил — один раз спросить: «Будешь после поста разбирать комментарии и писать тем, кто в ICP?» (достаточно кратко, без навязчивости).
- **Референс/эмуляция:** Есть ли у пользователя пример поста, с которого он снимает структуру? Если пишет «с нуля» и не искал референсы — предложить: «Можем подобрать структуру из референсов под твою цель (educate/inspire/entertain) — хочешь варианты?»
- **Цель перехода (куда ведём читателя):** Определить тип поста и главную CTA. Если пост про рассылку/Substack — основная цель перехода на Substack (ссылку в комментарии или в профиле), не размывать призывом в профиль. Если пост про что-то другое (карьера, продукт, опыт, инсайты) — одна из целей перехода на профиль LinkedIn; тогда применять рекомендации из раздела «Profile views» ниже и выбирать уместный момент для мягкого CTA в профиль.

**Как задавать вопросы:** коротко, по делу, 1–3 вопроса за раз. Не превращать в допрос: если пользователь уже всё учёл, ограничиться вердиктом и правками. Если контекст ясен (например, он явно просит «только проверь по SLAY») — не дублировать вопросы по теме/цели.

**В начале сессии про посты:** если пользователь говорит «хочу написать пост» или «помоги с LinkedIn», но не прислал черновик и не уточнил тему — сначала 1–2 вопроса: «Какую тему берёшь? Есть уже черновик или начнём с цели поста (educate / inspire / entertain)?» После ответа — дать практики/структуру или попросить черновик.

## Profile views (переходы в профиль)

**Когда применять:** для постов, где основная цель перехода — не Substack (не «подпишись на рассылку»), а знакомство с автором и заход в профиль LinkedIn. Для постов про Substack/рассылку главная CTA — переход на Substack; рекомендации ниже не делать приоритетом, чтобы не отвлекать от подписки.

**Если цель поста включает переходы в профиль — при генерации и проверке предлагать и проверять:**

1. **Личный stake в посте.** Текст от первого лица: «I did X», «What I learned», «What worked for me» — читатель связывает ценность с автором и чаще кликает по имени.
2. **Чёткая позиция или контринтуитив.** Сильный тезис («Most people do X. I think Y.») создаёт интерес «кто это говорит» и ведёт в профиль.
3. **Один явный вывод от тебя.** Не общие советы, а «вот правило, которому я следую» — тогда профиль смотрят за продолжением.
4. **Мягкий CTA в профиль (выбирать момент).** Не в каждом посте; когда уместно — в конце одна фраза: «I share more on [topic] in my profile / featured section» или «If you want the full framework, it’s in my featured section.» Не размывать основной призыв (вопрос, фидбек, подписка на Substack).
5. **Профиль готов к заходу.** Напоминать: заголовок профиля должен явно говорить, какую проблему решаешь и для кого; в Featured — хотя бы один пункт (ресурс, оффер), чтобы переход имел смысл.
6. **Вовлечение.** Ответы на комментарии под постом и комментарии у других повышают заходы в профиль; можно один раз напомнить про работу с комментариями.

При проверке черновика: если пост не про Substack — спросить или отметить, учтена ли цель «переход в профиль», и предложить 1–2 пункта из списка выше (личный stake, мягкий CTA в профиль), если их ещё нет.

## References (источники)

Все референсы лежат в папке скилла:

- **references/** — markdown-файлы с выжимками из видео, статей, курсов. Имена файлов — по смыслу (например `content-framework-and-leads.md`, `hook-formulas.md`).

При ответе всегда опираться на содержимое `references/`: цитировать, указывать источник, не придумывать практики «из головы».

**Разделение в референсах:** правила постинга в LinkedIn (хуки, структура, консистентность, метрики) — универсальные; рекомендации по инструментам (в т.ч. Taplio) — опциональные способы достичь результата (виральность, поиск паттернов, планирование). Не требовать от пользователя конкретный софт; при совете «посмотреть виральный контент» можно упомянуть инструменты как вариант, не как обязанность.

## Process

### Step 1: Понять запрос

- Пользователь просит best practices → перейти к Step 2.
- Пользователь прислал черновик поста → перейти к Step 3.
- Пользователь просит сгенерировать новый пост (написать пост с нуля) → перейти к Step 3a.
- Пользователь хочет добавить новый референс → перейти к Step 4.

### Step 3a: Генерация нового поста (с нуля)

- Подобрать структуру и написать полный текст поста по правилам (хук, середина, CTA, хэштеги).
- **Сразу после выдачи текста**:
  - Сформировать один короткий English prompt для картинки (ситуация/боль + образ результата, без текста внутри изображения).
  - Вызвать через Shell команду:
    - `npm run nanobanana:generate -- --prompt "<english image prompt>" --image_size 16:9 --save_dir "00-Inbox/Generated_Images"`.
  - Если команда отработала успешно:
    - распарсить JSON из stdout и взять `saved_paths[0]`
    - **сразу открыть картинку в Cursor**: прочитать файл по пути `saved_paths[0]` (это покажет превью в редакторе)
    - выдать пользователю текст поста и **путь к сохранённому файлу картинки** (`saved_paths[0]`)
  - Если команда не доступна или упала, выдать только текст поста и рядом явным блоком показать готовую команду `npm run nanobanana:generate ...`, чтобы пользователь мог запустить её вручную.

### Step 2: Показать best practices и чек-лист

- Прочитать все файлы в `references/` (на текущий момент).
- Выдать структурированно:
  - Краткий обзор практик (темы, цель поста, эмуляция, лиды, фреймворк поста).
  - Чек-лист перед публикацией (из референсов; если в нескольких файлах — объединить в один список).
  - Список источников с названиями файлов.
- В чек-листе учитывать обязательные правила: заголовок в начале, хэштеги в конце, при генерации поста — также картинка через Nano Banana (см. «Mandatory rules for every LinkedIn post»). Учитывать референс courtney-johnson-winning-posts.md: короткий хук, триггер вовлечения в конце, форматирование (переносы, списки), ресайкл работающего контента; рекомендации по Taplio/инструментам — только как опция («можно посмотреть виральный контент в…»), не требовать.
- Включить в обзор/чек-лист **цель перехода**: если пост про Substack/рассылку — главная CTA Substack; если пост про другое — одна из целей переход в профиль, см. раздел «Profile views».
- Предложить: «Пришли черновик поста — проверю по этому чек-листу» или «Опиши тему — подберу структуру из референсов».

### Step 3: Проверка черновика

- Прочитать референсы и черновик пользователя (в т.ч. **hook-and-copy-lessons-1percent-ai.md**: хук понятен с первого прочтения, платформа не «в лицо», середина конкретная, явный коммитмент, без блока A/B-теста; **courtney-johnson-winning-posts.md**: анатомия поста, короткий хук, триггер вовлечения, язык аудитории, «from the scar not wound»).
- **Определить цель перехода:** пост про Substack/рассылку → основная CTA Substack, не продвигать переход в профиль как главную цель. Пост про другое → одна из целей — переход в профиль; проверить по разделу «Profile views» (личный stake, позиция/контринтуитив, явный вывод, уместный мягкий CTA в профиль) и предложить правки, если чего-то не хватает.
- Пройти по чек-листу и фреймворку (например SLAY): что соблюдено, что нет.
- Проверить обязательные правила: цепляющий заголовок в начале, хэштеги в конце (см. раздел «Mandatory rules for every LinkedIn post»).
- **Признаки AI-writing недопустимы.** При правках и при генерации текста постов соблюдать `.claude/reference/ai-writing-signs-banned.md`: без кластеров AI-словаря (pivotal, crucial, underscore, tapestry, delve, foster, showcase), без раздувания значимости (testament, vital role, evolving landscape, commitment to, vibrant), без формульных конструкций (Not only... but...; Despite X...). Простые "is/are/has"; нейтральный тон, без рекламного стиля. В постах не использовать → (только -> или перефраз).
- Дать короткий вердикт (например «готов к публикации» / «доработать») и 3–7 конкретных правок с отсылкой к референсам («по references/content-framework-and-leads.md: в конце добавь You/PS — вопрос или платитуду»).
- Не переписывать весь пост за пользователя без запроса — фокус на рекомендациях и примерах формулировок.

### Step 4: Добавление нового референса

- Если пользователь прислал ссылку (YouTube, статью): при необходимости использовать `/youtube-transcript` для видео или прочитать/резюмировать статью.
- Создать в `references/` новый файл с понятным именем (например `hook-formulas.md`, `carousel-structure.md`).
- В начале файла указать: источник (URL, название, дата), дату добавления в референсы.
- В теле: выжимка best practices, чек-листы, цитаты — так, чтобы потом по ним можно было проверять посты.
- Кратко сообщить пользователю: «Добавлен референс `references/имя.md`, в нём то-то и то-то».
