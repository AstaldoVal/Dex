# Teal UI: обучение разметке (custom)

**Команда:** `/teal-ui-learn-custom`

Этот скилл обучает меня структуре интерфейса Teal и помогает поддерживать в актуальном состоянии «карту селекторов» для ключевых страниц:
- **Список вакансий:** `https://app.tealhq.com/job-tracker`
- **Карточка вакансии:** `https://app.tealhq.com/job-tracker/{jobId}`
- **Список резюме:** `https://app.tealhq.com/resume-builder/resumes`
- **Редактор резюме с превью:** `https://app.tealhq.com/resume-builder/resumes/{resumeId}/preview`
- **Matching резюме ↔ вакансия:** `https://app.tealhq.com/resume-builder/resumes/{resumeId}/matching`

Все знания о структуре и селекторах складываются в файл `.claude/reference/teal-ui-map.md`. Этот файл можно постепенно доучивать, когда Teal меняет верстку или когда появляются новые типы блоков опыта.

## Когда вызывать

- **Перед автоматизацией Teal** (например, массовое создание резюме, анализ matching, парсинг вакансий из job tracker).
- **После изменений в интерфейсе Teal**, когда скрипты или предыдущие инструкции начинают ломаться из-за новых селекторов.
- **Когда вы добавили новые типы опыта / блоков в резюме** и хотите, чтобы я понимал, где и как они отображаются в UI (например, новый AI‑резюме, затем iGaming‑резюме).

## Что я делаю при `/teal-ui-learn-custom`

### Шаг 0. Одна команда: вход + изучение страниц

Запуск **всего процесса** (вход в Teal по email при необходимости + обход страниц и сохранение HTML и селекторов) одной командой:

- **`npm run job-search:teal-ui-learn`**

Требования: в `.env` заданы `TEAL_EMAIL` и `TEAL_PASSWORD` (для входа по email, если сессия истекла). Если основной Chrome занят, скрипт автоматически запустит окно в отдельном профиле (`00-Inbox/Job_Search/teal/.chrome-profile`); в нём при первом запуске нужно один раз войти в Teal.

Каждый шаг логируется в один файл: **`00-Inbox/Job_Search/teal/teal-ui-learn.log`**. В логе: номер шага, название, статус [OK]/[FAIL], при необходимости деталь. В конце — блок **ИТОГ** (статус УСПЕХ/ОШИБКА), список **Что сделано** и при наличии **Ошибки**.

Результаты: HTML страниц и `selectors-report.txt` в `00-Inbox/Job_Search/teal/`; при первом прогоне в `.claude/reference/teal-ui-map.md` подставляются найденные jobId и resumeId. Дополнительно сохраняется **`teal-resume-experience.json`** — структура опыта (компании, позиции, буллеты) и состояние чекбоксов (какие пункты включены/выключены в резюме). Дальше можно заполнять селекторы по блокам в карте по сохранённому HTML и отчёту.

**Работа со страницей детального резюме (preview):** любой скрипт, которому нужны «какие пункты опыта и какие чекбоксы включены», должен использовать модуль **`.scripts/job-search/teal-resume-experience.cjs`**:
- **`extractResumeExperienceFromPage(page)`** — вызвать после перехода на resume preview; возвращает актуальные компании, позиции, буллеты и флаг `included` у каждого буллета.
- **`loadResumeExperience(TEAL_DIR, { resumeId })`** — прочитать последнее сохранённое состояние из `teal-resume-experience.json` (если передан `resumeId`, вернёт `null`, если в файле другой резюме).
- **`saveResumeExperience(TEAL_DIR, data, resumeId)`** — сохранить структуру (вызывается автоматически в teal-ui-learn после извлечения).
Таким образом, со страницей детального резюме мы работаем, опираясь на эти данные: либо только что извлекли с живой страницы, либо загрузили из JSON для того же резюме.

Опционально: `TEAL_JOB_ID=... TEAL_RESUME_ID=... npm run job-search:teal-ui-learn` — использовать указанные ID вместо первых из списка.

### Шаг 1. Собрать примеры и входные данные

- **Если пользователь дал явные URL** страниц (как в примерах в запросе) — использовать их напрямую.
- Если URL нет, **попросить**:
  - Один актуальный `jobId` для примера карточки вакансии.
  - Один или несколько `resumeId` для примеров резюме (AI, iGaming и т.п.).
- Зафиксировать эти ID и URL в секции «Примеры ID и URL» файла `.claude/reference/teal-ui-map.md` без лишних деталей содержания (только структура и примеры).

### Шаг 2. Открыть страницы Teal в браузере

- Использовать доступные браузерные инструменты среды (например, MCP браузер, `browser-use` или интеграцию через локальный браузер / Playwright).
- Для каждой целевой страницы:
  - Перейти по соответствующему URL.
  - Убедиться, что пользователь **авторизован в Teal**. Если показывается страница логина, попросить пользователя залогиниться и подтвердить, затем продолжить.
  - Дождаться полной загрузки страницы (аналог `networkidle`), прежде чем читать DOM.

### Шаг 3. Исследовать DOM и локаторы

Для каждой из пяти целевых страниц:

- Получить HTML‑содержимое страницы и при необходимости сделать скриншот, чтобы визуально понимать расположение блоков.
- Найти и зафиксировать:
  - **Основные блоки:** заголовок, подзаголовок, метаданные (компания, локация, статус и т.п.).
  - **Списки элементов:** вакансии в job tracker, записи опыта в резюме, разделы matching (Match Score, Hard Skills, Soft Skills, Other).
  - **Интерактивные элементы:** кнопки добавления/редактирования опыта, переключатели, вкладки.
- Для каждого важного блока определить максимально устойчивый локатор:
  - В приоритете: `data-testid`, `data-qa`, `aria-label`, семантические роли, стабильные CSS‑классы.
  - Избегать хрупких селекторов вроде `:nth-child()` или длинных цепочек с привязкой к случайным классам.

### Шаг 4. Обновить карту селекторов `teal-ui-map.md`

- Открыть файл `.claude/reference/teal-ui-map.md`.
- Для **каждой страницы** обновить соответствующую секцию:
  - Добавить или скорректировать список блоков:
    - **Блок:** короткое описание того, какую информацию содержит (например, «Заголовок вакансии в списке job tracker»).
    - **Селектор / локатор:** выбранный CSS / locator / роль (например, `data-testid="job-row-title"` или `role=heading[name="/Senior Product Manager/"]`).
    - **Пример содержимого:** 1 короткая строка с примерным текстом (без чувствительных данных).
- Если какие‑то селекторы устарели:
  - Явно пометить пункт как `- **Статус:** устаревший` и добавить рядом новый рабочий селектор.

### Шаг 5. Связать структуру с типами опыта

Особое внимание уделить тому, **как в DOM представлены блоки опыта в резюме**:

- Для AI‑резюме (пример, который вы уже дали):
  - Определить, в каких контейнерах лежат:
    - Заголовок роли, компания, период.
    - Основные буллеты / достижения.
  - Зафиксировать логику: как различать отдельные записи опыта в DOM.
- Позже, когда вы дадите пример **iGaming‑резюме**, выполнить те же шаги и:
  - Проверить, одинаковая ли структура DOM, или отличаются классы/селекторы.
  - Обновить карту селекторов так, чтобы она описывала общую модель (а не только один пример резюме).

### Шаг 6. Самообучение и последующие запуски

- При каждом следующем вызове `/teal-ui-learn-custom`:
  - Сначала **прочитать** существующий файл `.claude/reference/teal-ui-map.md`.
  - Сравнить описанную там структуру с фактическим DOM на страницах.
  - Выявить расхождения (сломанные селекторы, новые блоки, измененная иерархия).
  - Акуратно обновить только изменившиеся части, сохраняя историю и пометки об устаревших селекторах.

## Заметки

- **Custom‑скилл:** эта команда живет в `.claude/skills/teal-ui-learn-custom/` и защищена от перезаписи при обновлениях Dex.
- **Безопасность:** в `.claude/reference/teal-ui-map.md` сохраняем только структуру, селекторы и короткие примерные тексты, но не полные описания резюме или вакансий.
- **Локальные сценарии:** если нужно, этот скилл может опираться на отдельные скрипты (например, Playwright/Node/Python) для полуавтоматического сбора DOM и селекторов, но ключевое — чтобы все знания о структуре в итоге попадали в один источник правды: `teal-ui-map.md`.
