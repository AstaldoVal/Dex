# Idea Evaluation: Say No to Say Yes

Prioritization is not about saying yes. It is about saying no. Great PMs kill 90% of ideas to protect the 10% that move metrics. Use this framework when evaluating any idea, feature request, or initiative.

## When to Use

- User shares a new idea and asks "what do you think?"
- User proposes a feature, project, or initiative
- User asks to prioritize a list of options
- User mentions "we should add X" or "let's build Y"
- Any request to evaluate or compare ideas

## The 3-Layer Framework

### Layer 1: Capture (Do Not Act)

- Capture every idea immediately (email yourself, note in inbox)
- Do not evaluate in the moment
- Schedule 30–60 min weekly to process
- Let ideas marinate before deciding

**Rule:** Act on nothing until it passes Layer 2 and 3.

---

### Layer 2: Unbreakable Principles

Before touching backlog or backlog-like lists, define 3–5 product principles. Examples:

1. "Does this move our core metric by 10%+?"
2. "Can we ship this in 4 weeks with current resources?"
3. "Does this solve a problem users actually have?"

Principles are armor against shiny objects. If the idea fails any principle, it is a no.

---

### Layer 3: Problems, Not Solutions

Prioritize problems, not features. When someone says "we need dark mode," ask:

- What problem does this solve?
- How many users have this problem?
- What is the business impact of solving it?

Reframe solution-first ideas into problem-first. If the problem is weak or rare, the idea is a no.

---

## The Yes/No Cost Test

**Every time you say yes, calculate what you are saying no to.**

That "quick win" feature that takes 2 weeks?
- 2 weeks not spent on your core metric
- At a 50-person team: 100 person-weeks
- At $300K average comp: ~$1.15M opportunity cost

Suddenly that "quick win" is expensive.

Ask: "What am I saying no to if I say yes to this?"

---

## Evaluation Process

When user shares an idea:

1. **Reframe (if solution-first):** "You proposed [X]. What problem does this solve, and for whom?"
2. **Apply principles:** Run the idea against the user's 3–5 product principles (ask for them if not defined).
3. **Calculate opportunity cost:** "If we do this, what do we not do? What is the cost in time and focus?"
4. **Recommend:** Yes / No / Defer with clear rationale.
5. **If No or Defer:** "What would need to change for this to become a yes?"

---

## Output Format

- **Idea:** [One-line description]
- **Problem it solves:** [Reframed from solution]
- **Principles check:** [Pass/Fail per principle]
- **Opportunity cost:** [What we say no to]
- **Verdict:** Yes / No / Defer
- **Rationale:** [2–3 bullets]
