# Hooks: когда и для чего настраивать

Скилл помогает понять, что такое hooks в контексте Dex, где они работают, и **в каких кейсах их имеет смысл настраивать**. Конфигурация самих hooks делается в Claude Code (CLI или Desktop), не в репозитории Dex.

## Purpose

В репо Dex hooks не описаны и не настроены. Пользователь может не знать, для каких флоу они полезны. Этот скилл даёт рекомендации по сценариям и отсылает к справочнику.

## When to Use

- Пользователь спрашивает про hooks, автоматизацию по событиям, «уведомление по завершении», «экспорт перед компакцией».
- Обсуждается переход на Claude Code или настройка автоматических действий при старте сессии или после инструментов.
- В контексте dex-improve или обсуждения улучшений упоминаются «hooks», «PostToolUse», «SessionStart».

## What Are Hooks (кратко)

**Hooks** — автоматические сценарии по событиям в **Claude Code** (не в Cursor). Они выполняются гарантированно при каждом срабатывании события.

- **SessionStart** — при открытии сессии (загрузка контекста).
- **PreToolUse** — перед вызовом инструмента (проверка, подстановка контекста).
- **PostToolUse** — после вызова инструмента (уведомление, экспорт, пост-обработка).

В Cursor hooks не доступны; в Dex в репозитории они не настроены. Подробнее: `.claude/reference/hooks-in-dex.md`.

## Рекомендации: для каких флоу полезны hooks

Выдать пользователю список в формате «флоу → какой hook и зачем». Использовать таблицу или маркированный список.

1. **Уведомление по завершении длинного флоу**  
   **Флоу:** full LinkedIn→Teal, экспорт задач в Linear, генерация дайджеста, тяжёлые скрипты.  
   **Hook:** PostToolUse (или аналог после завершения скрипта/инструмента).  
   **Зачем:** не держать окно открытым; получить сигнал «готово» (локальное уведомление, напоминание, сообщение в чат).

2. **Экспорт / бэкап перед компакцией контекста**  
   **Флоу:** длинная сессия с полным флоу или массовыми операциями; перед сбросом или сжатием контекста.  
   **Hook:** PreToolUse перед компакцией или отдельный «before-compact» (если есть в Claude Code).  
   **Зачем:** сохранить ключевое состояние (последний шаг full-flow, список созданных тикетов) в vault (файл в `00-Inbox/` или обновлённый `linear_sync.json`), чтобы не потерять прогресс.

3. **Загрузка контекста в начале сессии**  
   **Флоу:** ежедневная работа в Claude Code (планирование, задачи, приоритеты).  
   **Hook:** SessionStart.  
   **Зачем:** автоматически подставить Quarter Goals, Week Priorities, Pillars, срочные задачи из `03-Tasks/Tasks.md`, чтобы не запрашивать вручную каждый раз.

4. **После сохранения встречи**  
   **Флоу:** запись заметок в `00-Inbox/Meetings/`.  
   **Hook:** PostToolUse при записи файла в эту папку.  
   **Зачем:** предложить или запустить обработку (process-meetings, извлечение задач, обновление person pages), если это поддерживается в Claude Code.

5. **Перед тяжёлой командой**  
   **Флоу:** запуск full-flow, массовый экспорт, долгие скрипты.  
   **Hook:** PreToolUse перед соответствующим инструментом/командой.  
   **Зачем:** краткое напоминание, что процесс займёт время и не нужно повторять вызов; опционально проверка готовности (браузер открыт, ключи настроены).

6. **Сохранение learnings / паттернов**  
   **Флоу:** конец сессии или после важного решения.  
   **Hook:** SessionEnd или PostToolUse после определённых действий (если доступно).  
   **Зачем:** записать выводы в `System/Session_Learnings/` или аналог, чтобы не забыть.

## Output

- Краткое объяснение, что такое hooks и где они работают (Claude Code, не Cursor).
- Список рекомендуемых флоу и соответствующих типов hooks (как выше).
- Ссылка на `.claude/reference/hooks-in-dex.md` и на официальную документацию Claude Code (hooks).

## Notes

- Не обещать настройку hooks внутри репо Dex: конфигурация делается в Claude Code.
- Если пользователь в Cursor — пояснить, что для гарантированных hooks нужен Claude Code (CLI или Desktop); в Cursor можно опираться только на инструкции в CLAUDE.md (без гарантии выполнения при каждом событии).
