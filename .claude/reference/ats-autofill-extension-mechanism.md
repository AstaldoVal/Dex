# Как экстеншн подставляет значения в ATS-форму

**Открытие формы в твоём Chrome (с расширением):** из корня репо  
`npm run job-search:open-in-chrome -- "<URL>"`  
Тот же способ, что и для парсинга LinkedIn (open-links, linkedin-capture): `open -a "Google Chrome"` на macOS. Скрипт: `.scripts/job-search/open-url-in-chrome.cjs`.

Кратко: при открытии страницы формы экстеншн определяет, что это ATS-форма, загружает профиль, находит на странице поля по подписям (лейблам), подставляет значения и синхронизирует с фреймворком (React/Vue), чтобы форма «увидела» изменения.

---

## 1. Где и когда запускаться

**Домены (content_scripts в manifest):**
- `https://jobs.ashbyhq.com/*`
- `https://*.careers.hibob.com/*`
- `https://jobs.elastic.co/*`, `https://www.okta.com/*` (и другие Greenhouse-хосты по мере добавления)
- `https://careers.fyul.com/*` (и другие Teamtailor — один скрипт на все careers.*)

**Когда:** `run_at: "document_idle"` или после небольшой задержки (setTimeout 1–2 s), чтобы SPA успел отрисовать форму. Для Ashby — после загрузки можно проверить, активна ли вкладка Application; для Teamtailor — форма появляется после клика Apply, тогда автозаполнение можно запускать по кнопке в расширении или по повторной проверке DOM через несколько секунд.

---

## 2. Откуда брать профиль

Расширение не имеет доступа к произвольным файлам на диске. Варианты:

**A. Локальный сервер (как у digest)**  
Текущий сервер (localhost:8766) может отдавать JSON профиля из репозитория. В манифесте уже есть `host_permissions` на localhost. Экстеншн при старте на ATS-странице делает `fetch('http://localhost:8766/ats-profile')` и получает содержимое `ats-application-profile.json`. Профиль один раз подтягивается из Dex, дальше им заполняем форму.

**B. chrome.storage**  
Пользователь один раз копирует JSON (или вставляет поля в options-странице расширения) → сохраняется в `chrome.storage.local`. Content script читает оттуда. Минус — дублирование: правки в репо не попадают в расширение, пока пользователь снова не вставит профиль.

**Рекомендация:** A, если локальный сервер уже поднят для job capture; иначе B с возможностью «импорт из файла» на options-странице.

---

## 3. Как найти поле на странице

- По **лейблу**: для каждого ключа профиля (first_name, email, …) есть массив строк в `label_variants` (например `["First Name", "First name", "Name"]`). Обходим все видимые на странице элементы с текстом (label, span, div, placeholder, aria-label) и ищем совпадение (нормализованное: trim, toLowerCase, убрать лишние пробелы; для частичного совпадения — строка лейбла содержится в тексте элемента или наоборот).
- Связь **лейбл → инпут**:
  - У `<label for="id">` ищем `document.getElementById(id)` или `document.querySelector('[id="..."]')`.
  - Если лейбл оборачивает инпут: `label.querySelector('input, select, textarea')`.
  - Иначе ищем следующий за лейблом инпут в общем родителе (например `label.parentElement.querySelector('input, select, textarea')` или обход вверх по DOM и поиск следующего инпута).
- Для **select / radio (Yes/No)**: находим блок с вопросом (по тексту из label_variants), затем внутри него ищем `input[type="radio"]` или `select option` с текстом/значением "Yes" или "No" и выбираем нужный (клик по radio или установка value у select + dispatch событий).

Поля **Resume** и **Cover Letter** (file input) не трогаем — пользователь загружает вручную.

---

## 4. Как подставить значение так, чтобы форма «увидела»

Многие ATS-формы на React/Vue. Просто присвоить `input.value = "..."` может не обновить внутренний state. Нужно:

1. Установить `input.value = value` (и для select — `select.value = value`).
2. Вызвать на элементе события, чтобы фреймворк зарегистрировал изменение:
   - `input.dispatchEvent(new InputEvent('input', { bubbles: true }));`
   - `input.dispatchEvent(new Event('change', { bubbles: true }));`
   Для select достаточно `change`. Для contenteditable — установка `innerText`/`textContent` и затем `input`-событие.
3. При необходимости один раз вызвать `input.focus()` и затем `input.blur()` — некоторые формы валидируют на blur.

Для полей с автокомплитом (например Location на Ashby) может понадобиться: установить значение, вызвать события, затем симулировать клик по варианту из выпадающего списка, если он появился, или оставить как есть, если форма принимает произвольный текст.

---

## 5. Порядок и однократность

- Заполнять поля в фиксированном порядке (например: first_name → last_name → email → phone → …), чтобы не путать соседние лейблы.
- Перед подстановкой проверять: если поле уже заполнено (value не пустой), можно пропускать или перезаписывать — настраиваемо. Так избегаем двойного срабатывания при навигации внутри SPA.

---

## 6. Сводка по шагам

1. Пользователь переходит на страницу ATS-формы (Ashby, Greenhouse, HiBob, Teamtailor и т.д.).
2. Content script на этой странице запускается (по match в manifest).
3. (Опционально) Определить ATS по URL (ashbyhq.com, hibob.com, …) и при необходимости подождать вкладку «Application» или появление формы после «Apply».
4. Загрузить профиль: `fetch` с localhost или чтение из `chrome.storage.local`.
5. Для каждого ключа профиля (кроме file-полей): по `label_variants` найти лейбл на странице, от него найти инпут/select, подставить значение из профиля, вызвать `input`/`change` события.
6. Для Yes/No: найти вопрос по тексту, найти соответствующий radio/select, выбрать Yes или No по значению в профиле.

После этого пользователь при необходимости загружает резюме и cover letter вручную и отправляет форму.

---

## 7. Где это реализовать

- **Вариант 1:** новый content script в существующем расширении Dex LinkedIn Job Capture (например `ats-autofill.js`), новые `content_scripts` в manifest с `matches` на перечисленные ATS-домены, профиль с localhost или storage.
- **Вариант 2:** отдельное расширение только для автозаполнения ATS, свой manifest и скрипты, профиль через options или тот же localhost.

В обоих случаях логика «найти по лейблу → подставить значение → dispatch событий» одна и та же; разница только в наборе доменов и в том, откуда читается профиль.
