# Claude GitHub App и MCP-профили по сценариям

Два отдельных блока: (1) что имеется в виду под «Claude как GitHub App» и созданием issue с телефона с @Claude; (2) что такое «профили MCP по сценариям» и как это может работать в Dex.

---

## 1. Claude как GitHub App (issue с телефона, @Claude)

### Что имеется в виду

Речь идёт об интеграции **Claude с GitHub** через официальное приложение [GitHub App — Claude](https://github.com/apps/claude):

- В репозитории или организации устанавливается приложение Claude.
- В **issues и pull requests** можно упомянуть **@claude** (в описании или в комментарии).
- Claude получает контекст (issue, PR, при необходимости код) и может: ответить в комментарии, предложить изменения, создать PR, следовать правилам из `CLAUDE.md` репозитория и т.д.

**«Issue с телефона»:** имеется в виду обычное создание issue в GitHub с любого устройства (мобильный браузер, приложение GitHub). После создания в теле issue или в комментарии можно написать @claude и описать задачу — бот отреагирует в рамках возможностей приложения. То есть это не отдельный «мобильный флоу», а использование стандартного GitHub-интерфейса с телефона + упоминание @claude.

### Состояние в Dex

В репозитории Dex эта интеграция **не разобрана и не настроена**: нет шагов установки приложения, настройки секретов (`ANTHROPIC_API_KEY`), примеров использования @claude в issues. Документация по интеграции лежит на стороне Anthropic/Claude (например [Using the GitHub integration](https://support.claude.com/en/articles/9945670-using-the-github-integration), [Claude Code GitHub Actions](https://docs.anthropic.com/en/docs/claude-code/github-actions)).

### Что можно сделать дальше

- Добавить в `.claude/reference/` или в `06-Resources/Dex_System/` краткую памятку: что такое Claude GitHub App, как установить, что даёт @claude в issues/PR, ссылки на официальные инструкции.
- При необходимости описать сценарий «создал issue с телефона → написал @claude и описал задачу → получил ответ/план в комментарии» как один из вариантов ввода задач в workflow.

## 2. Профили MCP по сценариям (PM flow, job search и т.д.)

### Что имеется в виду

Сейчас в Dex набор MCP-серверов задаётся глобально (например в `.cursor/mcp.json` или аналоге): один список серверов на всё. **Профиль MCP по сценарию** — это идея включать разные наборы MCP в зависимости от текущей задачи:

- **PM flow:** Linear, Figma, Notion (если используются), возможно Nano Banana для диаграмм — всё, что нужно для продукта, дорожных карт, тикетов.
- **Job search:** career MCP, Gmail (письма с вакансиями), возможно резюме/Teal-интеграции — без лишних серверов для дизайна или разработки.
- **Meetings / daily:** Calendar, Granola, Work (tasks), Reminders — минимум для планирования и встреч.
- **Writing / content:** не обязательно Linear или Figma; фокус на документах, возможно Notion.

То есть не «все серверы всегда», а **наборы по сценарию**, чтобы контекст и лимиты использовались под задачу.

### Как это может работать

Варианты (без обязательной реализации в репо):

1. **Документация-рекомендации**  
   В репозитории хранится один справочный файл (например этот или `mcp-profiles-by-scenario.md`): таблица сценариев и списки MCP, которые для них целесообразно включить. Пользователь вручную включает/выключает серверы в Cursor/Claude Code под текущий сценарий.

2. **Скилл-подсказка**  
   Скилл (например `/mcp-profiles` или раздел в `/dex-level-up`): пользователь называет сценарий («PM», «job search», «meetings»); скилл возвращает рекомендацию «для этого сценария включи: Linear, Figma, …» и кратко зачем. Конфигурацию пользователь меняет сам.

3. **Профили в конфиге (если платформа позволит)**  
   В будущем, если у Cursor/Claude Code появится поддержка именованных профилей MCP (например «cursor-mcp-profile: pm»), в репо можно хранить готовые конфиги: `mcp.pm.json`, `mcp.job-search.json`, и инструкцию по переключению.

4. **Один «лёгкий» конфиг по умолчанию**  
   По умолчанию включены только самые частые серверы (Work, Calendar, возможно Granola); при переходе на «тяжёлый» сценарий (PM, job search) пользователь добавляет серверы по рекомендации из документа или скилла.

### Что сделано в Dex сейчас

Отдельных **профилей MCP по сценариям в репозитории нет**: нет ни конфигов по сценариям, ни единого места, где перечислены рекомендуемые наборы для PM flow, job search и т.д. Эту роль может выполнить справочник (как раздел выше) и скилл-рекомендация.

---

## Итог

- **Claude GitHub App:** интеграция через @claude в issues/PR; создание issue с телефона = обычный GitHub + @claude. В Dex не разобрано; при необходимости добавить краткую памятку и ссылки на официальную документацию.
- **MCP-профили по сценариям:** идея — разные наборы MCP под задачу (PM, job search, meetings). Может работать через документ-рекомендации и скилл, который по названию сценария подсказывает, какие MCP включить; при появлении поддержки профилей на платформе — хранить готовые конфиги в репо.
