# Superpowers Guide (Dex)

## Что такое Superpowers

- Superpowers в контексте Dex это набор операционных навыков (`skills`) для процесса разработки.
- Это не CLI-команды в классическом смысле.
- Это режимы и протоколы работы, которые агент применяет по триггеру задачи.

## Список команд (skills) Superpowers

1. `using-superpowers`
 - Входной протокол: как подключать нужный skill перед ответом и работой.
 - Когда использовать: в начале сложной сессии, чтобы дальше работать дисциплинированно.

2. `brainstorming`
 - Предпроектный этап: уточнение требований, границ, рисков, вариантов решения.
 - Когда использовать: до реализации новой фичи или изменения поведения.

3. `writing-plans`
 - Формирует пошаговый план реализации по требованиям.
 - Когда использовать: есть задача больше одного шага и нужно зафиксировать порядок работ.

4. `executing-plans`
 - Выполнение уже готового плана с checkpoint-логикой.
 - Когда использовать: план согласован и его нужно пройти последовательно.

5. `dispatching-parallel-agents`
 - Распараллеливание независимых подзадач.
 - Когда использовать: есть два и более независимых блока (например тесты, документация, рефактор разных модулей).

6. `subagent-driven-development`
 - Реализация через несколько специализированных сабагентов.
 - Когда использовать: крупная задача, где выгодно разделить ответственность.

7. `test-driven-development`
 - TDD-цикл: сначала тесты, потом код.
 - Когда использовать: новая логика, критичные изменения, риск регрессий.

8. `systematic-debugging`
 - Системный дебаг: гипотеза -> проверка -> локализация -> фиксация.
 - Когда использовать: баги, нестабильные тесты, плавающие падения.

9. `verification-before-completion`
 - Обязательная верификация перед финальным статусом: тесты, линты, smoke, фактические артефакты.
 - Когда использовать: перед финальным отчётом, merge или release.

10. `requesting-code-review`
 - Подготовка изменений к ревью: что сделано, риски, что проверить.
 - Когда использовать: после значимого куска реализации.

11. `receiving-code-review`
 - Правильная обработка ревью-комментариев: валидация замечаний, корректные правки.
 - Когда использовать: пришёл фидбек по PR или изменениям.

12. `using-git-worktrees`
 - Изоляция работы в отдельном worktree или ветке.
 - Когда использовать: параллельные фичи, эксперименты, минимизация конфликтов.

13. `finishing-a-development-branch`
 - Завершение ветки: интеграция, подготовка к PR или merge, cleanup.
 - Когда использовать: фича готова и нужно безопасно закрыть цикл.

14. `writing-skills`
 - Создание или обновление самих skills.
 - Когда использовать: нужно расширить или стандартизировать поведение.

## Use-cases, где Superpowers наиболее полезен

1. Новая фича с неопределёнными требованиями
 - `brainstorming` -> `writing-plans` -> `executing-plans` -> `verification-before-completion`.

2. Сложный баг в проде или нестабильный сценарий
 - `systematic-debugging` -> (опционально `test-driven-development` для фикса регрессии) -> `verification-before-completion`.

3. Крупная задача, которую можно дробить
 - `dispatching-parallel-agents` или `subagent-driven-development` -> сбор результатов -> `verification-before-completion`.

4. Изменения повышенного риска (core logic, интеграции)
 - `test-driven-development` + `verification-before-completion` как обязательный минимум.

5. Работа в нескольких направлениях одновременно
 - `using-git-worktrees` для изоляции + `finishing-a-development-branch` при закрытии каждой ветки.

6. Ревью-цикл и стабилизация качества
 - `requesting-code-review` при передаче -> `receiving-code-review` при обработке замечаний -> `verification-before-completion`.

7. Масштабирование инженерного процесса
 - `writing-skills` для закрепления повторяемых процедур (единый verify-flow, release-flow, bug-triage-flow).

## Как использовать этот документ в Dex

- Это главный reference для выбора Superpowers-режима в инженерных задачах.
- Если задача неоднозначна, начинать с `using-superpowers`, затем выбирать следующий skill по сценарию.
- Для финализации любой значимой работы использовать `verification-before-completion`.
