# Research and web search MCP (Cursor)

Перед этим файлом рекомендуется открыть **`.claude/reference/research-capabilities-playbook.md`** — там единый практический playbook «что и когда использовать».

**Зачем:** веб- и академический ресёрч в Cursor через инструменты (MCP), с опорой на выдачу и при необходимости на «живую» страницу в браузере.

## Рекомендуемый порядок вызовов

1. **Сначала Exa (`exa-mcp`, `web_search_exa`).** Именно для **статей, авторов, people, research papers, компаний по смыслу**: в инструменте при необходимости задавать `category`: `research paper`, `people`, `company` (см. схему MCP). Так вы получаете семантически близкие URL и контекст без смешения с «голым» веб-поиском.
2. **При необходимости дозвонить Brave и/или Tavily.** Если выдачи Exa мало, нужны **свежие новости**, другой срез ссылок или извлечение под длинное обобщение: **brave-search-mcp**, **tavily-mcp**. Без платных ключей на этом шаге допустим **open-websearch-mcp** как запасной канал.
3. **Полный текст страницы или PDF, SPA, оболочка после JS:** открыть **URL в browser MCP** (cursor-ide-browser): снимок после рендера JS; для **PDF** — по прямой ссылке на файл в браузере, если открывается во вкладке, иначе ориентироваться на выдачу и зеркала или HTML-версии.

Итоговая цепочка по умолчанию: **Exa → (по ситуации) Brave/Tavily → browser MCP для глубины по конкретному URL.**

**Опционально, после того как ссылки и краткие выдержки уже есть:** **claude-code-mcp** (одноразовый вызов Claude Code CLI с доступом к вебу у **этого** агента): обогащение, сводка по нескольким источникам, «дожать» формулировку. См. раздел **Claude Code MCP (steipete)** ниже.

## Базовый набор (уже в `.cursor/mcp.json.source`)

В конфиге Dex по умолчанию уже есть **open-websearch-mcp** (DuckDuckGo, без ключа), **tavily-mcp** и **brave-search-mcp** (ключи из `.env`, иначе при синке отключаются). Отдельно в списке «что выбрать» их держать не нужно: это рабочая база после `cursor-sync-mcp.py` и перезапуска Cursor.

## Exa (семантический поиск, академия и широкий веб)

- **Сервер:** `exa-mcp` → `npx -y exa-mcp-server`.
- **Ключ:** `EXA_API_KEY` в **`.env`** (ключи: https://dashboard.exa.ai/api-keys ). Документация: https://exa.ai/docs/reference/exa-mcp
- **Зачем:** выдача и контекст ближе к «найди по смыслу», уместно для **научных статей, репозиториев, страниц компаний, глубокого ресёрча** рядом с обычным веб-поиском Brave/Tavily/DuckDuckGo.
- Без ключа в `.env` сервер **exa-mcp** при синке помечается **`disabled: true`**.

## Настройка (ключи и синк)

1. В **`.env`** (не коммитить): при необходимости `TAVILY_API_KEY`, `BRAVE_API_KEY`, `EXA_API_KEY`.
2. Из корня Dex: `python3 .scripts/cursor-sync-mcp.py`
3. Полностью перезапустить Cursor (quit и снова открыть).

## Claude Code MCP (steipete): веб и обогащение выдачи из Cursor

**Репозиторий:** https://github.com/steipete/claude-code-mcp

**Что это:** MCP-сервер с одним основным инструментом (обычно `claude_code`), который **в одном запуске** вызывает **Claude Code CLI** (`claude`) с флагом **`--dangerously-skip-permissions`**. Это **не** интерактивное окно Claude Code в терминале, а подпроцесс: в **`prompt`** передаёте задачу (в т.ч. «поищи в вебе и кратко обобщи» или «вот ссылки и сниппеты из Exa/Brave — выдели расхождения и вывод»), ответ возвращается в чат Cursor.

**Зачем вам (основной кейс):**

- **Обогащение и сводка** после того, как **exa-mcp / brave-search-mcp / tavily-mcp / open-websearch** (и при необходимости browser MCP) уже дали ссылки и фрагменты.
- **Дополнительный канал фактов** через возможности **Claude Code** (включая веб в рамках CLI), без ручного копипаста из отдельного сеанса `claude`.

**Не заменяет** первый шаг поиска: медленнее и дороже, чем прямые поисковые MCP; имеет смысл как **второй слой** по запросу или когда нужна связная многоабзацная сводка по уже собранному сырью.

**Требования:**

1. **Node.js 20+** и установленный **Claude Code CLI** (`claude` в PATH). Установка от Anthropic: см. документацию `claude code`, например `npm install -g @anthropic-ai/claude-code`.
2. **Один раз вручную** (требование CLI): выполнить в терминале `claude --dangerously-skip-permissions`, войти и **принять условия**, иначе MCP при вызове инструмента может падать. На macOS при первом запуске возможны запросы доступа к каталогам.
3. Синк конфига: `python3 .scripts/cursor-sync-mcp.py` и перезапуск Cursor.

**Опционально в `env` блока MCP (или `.env` не обязателен для этого сервера):**

- `CLAUDE_CLI_NAME` — если бинарь не `claude`, а другое имя или абсолютный путь (см. README репозитория).
- `MCP_CLAUDE_DEBUG` — оставьте **`false`** в боевом режиме: значение **`true`** может портить JSON MCP.

**Безопасность:** процесс Claude Code с **skip permissions** может **читать и менять файлы** в рамках того, что разрешено CLI, и выполнять команды. В промптах для **только веб-ресёрча** явно ограничивайте задачу (поиск, обобщение, цитаты), без лишних «почисти репозиторий» и т.п., если вы этого не хотите.

**Связка с Gemini в другом абзаце:** в репозитории steipete описан сценарий offloading на Claude Code с подпиской Anthropic; биллинг идёт по правилам **вашего** аккаунта Claude Code, не Cursor.

## Почему browser MCP, а не «Fetch по URL»

- Обычный **HTTP-запрос (Fetch)** почти всегда получает **сырой HTML**, как его отдал сервер в первый момент. На многих сайтах основной текст **появляется только после JavaScript**: пустая оболочка в HTML и контент дорисовывается в браузере. Тогда Fetch даёт мусор или заглушку, а ответ для ресёрча бесполезен.
- **cursor-ide-browser** открывает страницу как **настоящий браузер**, выполняет JS, строит DOM; вы получаете **снимок того, что видит пользователь** (текст, структура для кликов при необходимости).

**Практическое преимущество для вас:** после Brave/Tavily/Exa по ссылкам «не открывается смысл страницы» — не вычислять причину, а **открыть URL в browser MCP** и снять контент. Это не замена поиска, а **второй шаг**: поиск дал URL → браузер дал полный смысл страницы.

**Подключено ли:** **cursor-ide-browser** задаётся средой Cursor (встроенный MCP браузера), а не строкой в `mcp.json.source` Dex. Если в чате доступны инструменты вроде `browser_navigate` / снимок страницы, слой уже есть.

## Что значит «динамика»

**Динамические страницы** — сайт, где контент **дорисовывается скриптами** (React/Vue/SPA, бесконечные ленты, часть документации и дашбордов). Для них «скачать один раз HTML» мало; нужен **рендер в браузере**. В этом смысле **browser MCP** и про «динамику».

## Firecrawl и Puppeteer: суть и нужно ли вам

- **Firecrawl** — облачный сервис: отдаёте URL, они отдают **очищенный текст/markdown**, часто с обходом части технограниц. Удобно для **пакетного** извлечения с **множества** URL. Обычно **платно** после бесплатной квоты, ключ отдельно.
- **Puppeteer** — **локально** управлять Chrome/Chromium (клики, скролл, ожидание). Гибко, но **хрупко** (ломается от вёрстки), тяжелее в поддержке. Для LinkedIn в Dex по правилам **автоматизация браузера запрещена**; для остальных сайтов теоретически возможно, но это отдельный уровень сложности.

**Нужно ли по умолчанию:** чаще **нет**, если хватает связки **поиск MCP + browser MCP**. Имеет смысл, когда **очень много** URL и нужен **массовый** чистый текст (Firecrawl) или редкие кейсы, где даже встроенного браузера Cursor мало.

## Google Programmable Search (CSE)

Новые подключения **полного веб-поиска** через Google CSE **не опираются** как раньше; **Custom Search JSON API** для **новых** клиентов закрыт. Детали см. ранее в этой справке и на стороне Google. Для общего ресёрча используйте MCP выше, не CSE.

## Параллельный поиск: Cursor, Claude Code, Gemini и несколько MCP

- **В одном чате Cursor** модель может **подряд вызвать несколько инструментов** (например, выдачу Brave и отдельный запрос Exa) и потом **свести ответ**. Это и есть практическая «параллель» без отдельного оркестратора: достаточно явно сказать в запросе: «проверь через Exa для статей и через Brave для новостей, потом сравни».
- **Встроенный веб-поиск в UI Cursor** (если включён у модели) — это **не отдельный MCP** в `mcp.json`: агент в том же чате опирается на **подключённые MCP** плюс политику модели. Чтобы гарантированно использовать **ваш** стек (Brave, Exa, Tavily), надёжнее **вызывать именно эти MCP-инструменты**, а не рассчитывать только на общий «web» режим чата.
- **Claude Code** (терминальный агент Anthropic) — **отдельное окружение** от Cursor: список MCP в самом CLI **не совпадает** автоматически с `~/.cursor/mcp.json`. В Dex дополнительно подключён **claude-code-mcp**: из **этого** чата Cursor можно **одноразово** вызвать Claude Code для веба и сводок (см. раздел выше). Параллельно в нативном терминале `claude` можно вести отдельные сессии с **своим** набором MCP, если настроите их в конфиге Claude Code.
- **Gemini с Grounding (Google Search)** по API даёт **свой** канал фактов и цитат. В Cursor это можно подключить как **отдельный MCP** (например, community-сервер вроде `mcp-gemini-google-search` с `GEMINI_API_KEY`; пакет и название уточняйте по актуальной инструкции пакета). В Dex это **не включено по умолчанию**: при желании добавьте блок в **`mcp.json.source`** и переменные в **`.env`**, затем синк. Итог: можно иметь **несколько независимых каналов** (Exa + Brave + Gemini-grounding MCP) и просить модель **агрегировать** с явными источниками; в **Claude Code** такой MCP при необходимости подключается **отдельно** в его конфиге.

## Когда что использовать (кратко)

Порядок по умолчанию см. раздел **Рекомендуемый порядок вызовов** выше. По роли инструментов:

- Старт для статей, авторов, papers, компаний по смыслу: **exa-mcp** при ключе.
- Дозапрос новостей и второй срез ссылок: **brave-search-mcp** при ключе.
- Длинное извлечение под обобщение/RAG: **tavily-mcp** при ключе.
- Без ключа и быстро по вебу: **open-websearch-mcp**.
- Страница или PDF не читаются из сырого HTML / нужен рендер JS: **browser MCP** по URL.
- Сводка, обогащение и «дожать» вывод по **уже собранным** ссылкам и выдержкам: **claude-code-mcp** (инструмент `claude_code`), не как первый шаг простого поиска.
