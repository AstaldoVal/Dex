# Full flow LinkedIn → Teal: шаги и актуальные действия

Полный прогон: **URL поиска LinkedIn** → захват → дайджест → фильтр → описания 100% → добавление в Teal → создание резюме → match-score. Порядок: **1 → 2 → 3 → 4 → 5 → 6 → 7 → 8**.

---

## Термины и ключевые файлы

**Flow state (состояние потока)** — файлы `00-Inbox/Job_Search/teal/full-flow-state.json` и `full-flow-state.md`. В них записывается: на каком шаге остановились, пути к экспорту и дайджесту, **linkedinUrl** (URL поиска LinkedIn), статус (running/completed), команда для возобновления после сбоя. Нужны, чтобы не путать данные разных запусков и понимать, с какого шага продолжить.

**Evidence (доказательства по шагам)** — в папке `00-Inbox/Job_Search/teal/` лежат файлы с фактами по каждому шагу. Кто что пишет и зачем:

- **full-flow-evidence.json** — пишет основной скрипт Flow после шагов 1–5 (и подтягивает данные из step-6/7/8 после их выполнения). Содержит: ссылку на поиск LinkedIn (linkedinUrl), по каждому шагу — пути к файлам, счётчики, причину пропуска шага (если пропущен).
- **step-6-evidence.json** — пишет скрипт добавления вакансий в Teal (шаг 6). Содержит список добавленных вакансий: по каждой — jobId, linkedinUrl, company, title, tealJobUrl (ссылка на вакансию в Teal).
- **Шаг 7** пишет два файла:
  - **step-7-evidence.json** — сколько резюме создано (created), какие пропущены (skipped), сколько не удалось создать (failed). По skipped в конце Flow выводится нотификация со ссылками (см. «Дополнительно после успешного завершения»). Если failed > 0, Flow после шага 7 завершается с критической ошибкой; цель — 0% неудачных созданий.
  - **resume-to-job.json** — связка «id резюме в Teal → jobId, company, title» (по какой вакансии какое резюме создано).
- **step-8-evidence.json** — пишет скрипт match-score (шаг 8). Содержит: список обработанных резюме, итоги по match-score.

**Как в дайджесте появляется секция «Трекинг (LinkedIn → Teal)»:** после успешного шага 8 основной скрипт Flow вызывает функцию, которая читает **step-6-evidence.json** (список добавленных в Teal вакансий и их tealJobUrl), **resume-to-job.json** (чтобы по jobId получить id резюме и собрать ссылку на резюме в Teal) и **linkedinUrl** из flow state (или из full-flow-evidence.json). Из этих данных в конец файла дайджеста дописывается блок: ссылка на поиск LinkedIn и по каждой вакансии строка «название · компания», ссылка на вакансию в LinkedIn, на вакансию в Teal, на резюме в Teal. То есть секция трекинга собирается из step-6 + resume-to-job + URL поиска; step-7 и step-8 evidence в эту секцию не входят (они нужны для логов и отладки).

**Три файла после шагов 3–4 (итог этапа «описания»):**

1. **dex-linkedin-export-*.json** — полный экспорт из расширения Dex. Появляется или обновляется **один раз в конце** автопрохода по open-links: расширение по каждой странице пишет в jobs/&lt;id&gt;.json, а после прохода всех ссылок (если был Start auto-capture и save-server) отправляет на сервер один JSON со всеми вакансиями, в т.ч. work type: Remote/On-site/Hybrid. Лежит в `00-Inbox/Job_Search/data/`.
2. **Дайджест (search-*.md)** — markdown-файл со списком вакансий (ссылки, заголовки, компании, блоки с описанием). Путь: `00-Inbox/Job_Search/digests/linkedin/`.
3. **jobs/&lt;id&gt;.json** — по одной вакансии, полные данные: title, company, описание, work_type. Папка `00-Inbox/Job_Search/data/jobs/`. Самый полный источник описания для следующих шагов (шаг 6 и т.д.).

Шаги 3–4: открываются ссылки из дайджеста (open-links), расширение сохраняет по каждой вакансии данные в **jobs/&lt;id&gt;.json**. Полный экспорт **dex-linkedin-export-*.json** создаётся или обновляется **один раз в конце** автопрохода: когда все страницы пройдены, расширение (если был нажат Start auto-capture и поднят save-server) отправляет собранные данные на сервер — этот файл нужен для шага 5 (фильтр по remote/on-site/hybrid) и для завершения скрипта шага 4.

## Параметры запуска (когда какой шаг выполняется)

- **Запуск по URL поиска** — вы передаёте ссылку на поиск LinkedIn (`https://www.linkedin.com/jobs/search/?...`). Выполняются шаги 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 (шаг 1 не пропускается).
- **--from-digest &lt;файл&gt;** — дайджест уже готов (файл .md). Шаги 1 и 2 пропускаются; используются существующие экспорт (если есть) и дайджест. Дальше шаги 3, 4, 5, 6, 7, 8.
- **--from-text &lt;файл&gt;** — вакансия задана вставленным текстом. Название должности и компании извлекаются из файла: предпочтительно первая строка в формате «Title | Company» или «Title — Company» или «Title at Company», пустая строка, затем описание; при неоднозначном формате или отсутствии разделителя — из самого текста описания (эвристики deriveTitleFromDescription / deriveCompanyFromDescription). Шаги 1, 2, 3, 4 пропускаются; дайджест создаётся из файла. Дальше шаги 5, 6, 7, 8. **При запуске через агента:** перед выполнением flow агент должен показать определённые title и company, запросить подтверждение и только после него запускать скрипт; исправления пользователя можно сохранять для улучшения извлечения в будущем.
- **Single-job URL** — вы передаёте ссылку на одну вакансию (`https://www.linkedin.com/jobs/view/123...`). Шаг 1 пропускается: создаётся «синтетический» экспорт из одной вакансии, затем шаги 2 → 3 → 4 → 5 → 6 → 7 → 8.
- **--use-existing-export** — использовать уже сохранённый экспорт поиска (не запускать захват в браузере). Шаг 1 пропускается; берётся существующий файл экспорта из `data/`.
- **--step-by-step** — по одному шагу за запуск: выполняется только следующий шаг, после него в консоль выводится блок **«STEP N ARTIFACTS»** (пути к созданным файлам и краткое описание для проверки), состояние потока обновляется, скрипт завершается. Повторный запуск **той же команды** (тот же URL или тот же `--from-digest`) продолжает со следующего шага. Режим поддерживается только для запуска по URL (поиск или single-job) и для `--from-digest`; для `--from-text` не применяется.

## Шаг 1. Захват поиска LinkedIn (Capture)

**Когда выполняется:** при запуске по URL поиска, если не указаны параметры из списка выше (не `--from-digest`, не `--from-text`, не single-job URL и не `--use-existing-export`).

**Действия:**
- Запускается save server (если не запущен) на `http://127.0.0.1:8765/dex-save`.
- Запускается **linkedin-capture-run.cjs** с URL поиска LinkedIn.
- Расширение Dex в браузере пользователя открывает поиск и сохраняет вакансии через save server.
- Результат: файл экспорта **dex-linkedin-search-&lt;slug&gt;-&lt;date&gt;.json** в `00-Inbox/Job_Search/data/`.
- URL поиска сохраняется в flow state (`linkedinUrl`) и в evidence для секции трекинга в дайджесте (после шага 8).

**Результат шага:** путь к экспорту, количество вакансий.

---

## Шаг 2. Создание MD-дайджеста

**Когда выполняется:** после шага 1 (или при `--from-digest` / `--from-text` дайджест уже есть).

**Действия:**
- Запускается **generate-search-digest.cjs** с путём к экспорту.
- Дедуп по jobId, фильтр только PM/PO (для single-job или одной вакансии в экспорте фильтр PM/языка не применяется).
- Создаётся файл дайджеста в `00-Inbox/Job_Search/digests/linkedin/search-&lt;slug&gt;-&lt;date&gt;.md`.
- **Заголовок вакансии (title):** в дайджесте не допускаются плейсхолдеры «—» или пустое название. Если в экспорте нет title, скрипт подставляет его из **jobs/&lt;id&gt;.json** (если файл есть) или из текста описания (deriveTitleFromDescription). Вакансии, для которых не удалось определить title, пропускаются с предупреждением.

**Результат шага:** путь к дайджесту, количество вакансий в дайджесте.

---

## Шаг 3. Генерация HTML со ссылками на вакансии

**Когда выполняется:** после шага 2 (пропускается при `--from-text`).

**Действия:**
- Запускается **generate-digest-open-links.cjs** с путём к дайджесту.
- Создаётся HTML-файл **digest-open-links-&lt;baseName&gt;.html** в `00-Inbox/Job_Search/data/`.
- Этот HTML нужен, чтобы открыть ссылки на вакансии в браузере; расширение при открытии страниц дополняет полный экспорт (для шага 5) и сохраняет описания в **jobs/&lt;id&gt;.json** (шаг 4).

**Результат шага:** путь к HTML, количество ссылок = количеству вакансий в дайджесте.

---

## Шаг 4. Добавление описаний вакансий до 100%

**Когда выполняется:** после шага 3 (пропускается при `--from-text`).

**Действия:**
- Запускается **fetch-job-descriptions.cjs** с путём к дайджесту: поднимается сервер, в браузере открывается open-links HTML; **LinkedIn не открывается скриптами** — только расширение Dex в вашем браузере перехватывает страницы, сохраняет описания в **jobs/&lt;id&gt;.json** по каждой вакансии, а в конце прохода отправляет полный экспорт **dex-linkedin-export-*.json** на сервер (если был Start auto-capture и save-server).
- Проверяется, у скольких вакансий в дайджесте уже есть описание; при необходимости выполняются до 4 раундов retry (`--retry-only`).
- **Инжект без браузера (только для single-job):** если описание уже есть в **jobs/&lt;id&gt;.json** (например, получено ранее при открытии страницы), скрипт может подставить его в дайджест без открытия браузера и ожидания захвата — то есть «инжект» = вставка текста описания из файла в markdown дайджеста.

**Результат шага:** у всех вакансий в дайджесте заполнено поле с описанием. По каждой вакансии полные данные сохраняются в **jobs/&lt;id&gt;.json**. Если после всех retry остались вакансии без описания, Flow завершается с **критической ошибкой** (исключение): цель — 0% вакансий с ошибками; при появлении такой ситуации её нужно устранять (повторить открытие ссылок в браузере с расширением, проверить работу расширения и т.д.).

## Шаг 5. Фильтрация дайджеста по экспорту (remote/on-site)

**Когда выполняется:** после шагов 1–4. Шаг **пропускается** в трёх случаях:

1. **Single-job** — вы запустили Flow по ссылке на одну вакансию (`linkedin.com/jobs/view/...`). Дайджест из одной вакансии, фильтровать нечего.
2. **Один job в экспорте** — в файле экспорта только одна вакансия (например, ручной экспорт одной вакансии). Фильтр по remote/on-site для одной записи не имеет смысла.
3. **--from-digest** — вы передали готовый дайджест; экспорт может быть от другого запуска или отсутствовать. Чтобы не удалить вакансии по устаревшему экспорту, фильтр не применяется, дайджест остаётся как есть.

**Почему фильтр использует дайджест + полный экспорт:** полный экспорт **dex-linkedin-export-*.json** — это то, что расширение Dex записывает, когда вы открываете страницы вакансий (open-links). В нём по каждой вакансии есть **workType** (Remote / On-site / Hybrid). Скрипт **filter-digest-from-export.cjs** читает этот экспорт и удаляет из дайджеста строки, у которых тип работы on-site/hybrid (по вашим настройкам). То есть источник информации о типе работы — экспорт от расширения; файлы **jobs/&lt;id&gt;.json** содержат полное описание и тоже могут содержать work_type, но фильтр использует один общий экспорт как единый «снимок» от расширения.

**Действия (когда шаг не пропущен):**
- Ищется последний полный экспорт (dex-linkedin-export-*.json).
- Запускается **filter-digest-from-export.cjs** с путём к дайджесту и к полному экспорту.
- **Placeholder title (—):** если в строке дайджеста название должности «—» или пустое, скрипт перед записью пытается взять title из **jobs/&lt;id&gt;.json** или из описания (deriveTitleFromDescription). Если восстановить не удалось, в консоль выводится **[CRITICAL]** с jobId и URL; строку всё равно обновляют (company/workType), чтобы не терять данные фильтра.
- Из дайджеста удаляются вакансии on-site/hybrid по данным экспорта (остаются remote и подходящие под настройки).

**Результат шага:** обновлённый дайджест с меньшим или тем же числом вакансий.

**Опция --no-teal:** после шага 5 Flow завершается, шаги 6–8 не выполняются. Используйте, когда нужно только получить дайджест, заполнить описания и отфильтровать по remote, но не добавлять вакансии в Teal и не создавать резюме (например, сначала просмотреть дайджест и потом вручную добавить часть в Teal).

## Шаг 6. Добавление вакансий из дайджеста в Teal

**Когда выполняется:** после шага 5, только если не указан `--no-teal`.

**Источники данных (приоритет):**
- **Первый источник:** `jobs/<id>.json` (результат шага 4 — самый полный: описание, title, company, work_type с страницы вакансии).
- **Fallback:** экспорт поиска (шаг 1) — только если файла нет или описание короче 100 символов. Такая ситуация считается нештатной: логируется как **[CRITICAL]** и исправляется автоматически (см. ниже).

**Действия:**
1. **ensureJobsDataAsync** (только в режиме `--app`): перед сбором данных по каждой вакансии проверяется наличие `jobs/<id>.json` и длина описания (≥ 100 символов). Если файла нет или описание короткое:
   - в stderr выводится **`[CRITICAL] job <id>: jobs/<id>.json missing or description < 100 chars. Auto-fixing: fetching from LinkedIn…`**;
   - выполняется запрос страницы вакансии (fetchJobPageTitleCompanyAndDescription, при неудаче — Crawler UA);
   - результат записывается в `jobs/<id>.json`;
   - выводится **`[CRITICAL] job <id>: auto-fix OK`** или предупреждение, если описание всё ещё короткое.
2. Запускается **add-digest-jobs-to-teal-playwright.cjs** с путём к дайджесту, флагом **`--app`** (добавление через форму Teal в браузере) и **`--export <путь>`** (экспорт поиска шага 1; данные о вакансиях берутся из jobs/, экспорт передаётся для контекста шага 6).
3. Используется отдельный Chrome-профиль для Teal (основной Chrome может оставаться открытым).
4. Для каждой вакансии: проверка дубликата в Teal, при отсутствии — добавление через форму (вставка URL или описания); после успешного добавления сохраняется URL страницы вакансии в Teal (`tealJobUrl`).
5. Если после авто-исправления у вакансии по-прежнему нет описания ≥ 100 символов и используется экспорт, в stderr выводится **`[CRITICAL] ... Using export fallback. This should not happen after auto-fix.`**
6. Результаты шага пишутся в **step-6-evidence.json**: для каждой добавленной вакансии — jobId, linkedinUrl, company, title, tealJobUrl.

**Результат шага:** вакансии из дайджеста добавлены в Teal Job Tracker, evidence содержит ссылки на вакансии в Teal. Нештатные случаи (нет/короткое описание) логируются как CRITICAL и по возможности исправляются автоматически.

## Шаг 7. Создание резюме в Teal по дайджесту

**Когда выполняется:** после шага 6.

**Почему передаётся путь к дайджесту:** дайджест задаёт **список и порядок** вакансий (тот же набор, что добавлен на шаге 6). Фактические данные (title, company, описание) скрипт берёт из **jobs/&lt;id&gt;.json** при наличии файла — это самый актуальный источник после шага 4; дайджест используется только как fallback и для определения списка.

**Действия:**
- Запускается **teal-resume-batch-from-export.cjs** с путём к дайджесту (список/порядок из дайджеста, данные из jobs/ при наличии).
- Создаются копии резюме в Teal только для вакансий, добавленных на шаге 6 (TEAL_ONLY_ADDED_THIS_RUN=1).
- Выбор шаблона: iGaming vs AI/other по контексту вакансии; копия переименовывается под должность.
- Связь резюме ↔ вакансия записывается в **resume-to-job.json** (resumeId → { jobId, company, title }).
- В **step-7-evidence.json** пишутся: созданные (created), пропущенные из‑за «резюме уже есть» (skipped), число неудачных созданий (failed). Skipped на этом шаге не считается автоматически «нормой»: в конце Flow выводится **нотификация** по всем пропущенным (см. ниже).

**Результат шага:** у каждой добавленной в Teal вакансии должно быть создано резюме. Цель — **0% неудачных созданий** (failed = 0). Если после шага 7 в evidence оказалось failed > 0, Flow выводит **[CRITICAL]** и завершается с ошибкой; такие случаи нужно исправлять (повторить шаг 7, проверить Teal и т.д.).

---

## Шаг 8. Match-score (summary, target title, PDF, cover letter)

**Когда выполняется:** после шага 7.

**Действия:**
- Запускается **teal-resume-match-score.cjs** с путём к дайджесту.
- Для каждого резюме в Teal по вакансии из дайджеста: проверка процента совпадения; при &lt; 80% и наличии описания — цикл оптимизации Professional Summary (до 5 итераций) до достижения 80%+ или стабилизации.
- Установка Target Job Title, сохранение PDF и cover letter в папку Applied (например `~/Documents/Applied/&lt;Company&gt;/`).
- До 3 попыток запуска при падении скрипта (с паузой 15 с между попытками).

**Результат шага:** резюме доведены до 80%+ match, PDF и сопроводительные письма сохранены в Applied.

## После шага 8: секция трекинга в дайджесте

**Действия:**
- Вызывается **buildAndWriteDigestTrackingSection(digestPath)**.
- Читаются **step-6-evidence.json** (добавленные в Teal вакансии: jobId, linkedinUrl, company, title, tealJobUrl) и **resume-to-job.json** (jobId → resumeId).
- URL поиска LinkedIn берётся из flow state (`linkedinUrl`) или из flow evidence.
- В конец дайджеста записывается или обновляется секция **«Трекинг (LinkedIn → Teal)»**:
  - ссылка на источник дайджеста (поиск LinkedIn);
  - по каждой добавленной вакансии: **название · компания**, ссылка на вакансию в LinkedIn, ссылка на вакансию в Teal, ссылка на резюме в Teal;
  - время последнего обновления секции.

**Результат:** в одном месте в дайджесте виден полный путь: источник поиска → дайджест → вакансия в Teal → резюме в Teal.

## Дополнительно после успешного завершения

- **Нотификация по Step 7 skipped:** если в step-7-evidence.json есть пропущенные вакансии (skipped), Flow после секции трекинга в дайджесте выводит в консоль блок «Step 7 skipped (N item(s))» и по каждому пункту: компания, должность, jobId, причина пропуска, ссылка на вакансию в LinkedIn, при наличии — ссылка на вакансию в Teal (из step-6-evidence). Тот же список дописывается в конец **full-flow-state.md** (секция «Step 7 skipped»), чтобы можно было быстро перейти на нужную страницу и проверить.
- Обновление **last-processed** (job IDs по URL поиска) для инкрементальных запусков: при следующем прогоне по тому же поиску уже обработанные вакансии не добавляются в Teal повторно.
- Flow state переводится в статус `completed`, currentStep = null.

## Запуск

- По URL поиска:  
  `node .scripts/job-search/run-full-linkedin-teal-flow.cjs "https://www.linkedin.com/jobs/search/?..."`
- По URL одной вакансии:  
  `node .scripts/job-search/run-full-linkedin-teal-flow.cjs "https://www.linkedin.com/jobs/view/4371749875/..."`
- С существующим дайджестом (шаги 3–8):  
  `node .scripts/job-search/run-full-linkedin-teal-flow.cjs --from-digest 00-Inbox/Job_Search/digests/linkedin/search-....md`
- Из вставленного текста вакансии (шаги 5–8):  
  `node .scripts/job-search/run-full-linkedin-teal-flow.cjs --from-text path/to/job.txt`  
  Сначала только проверить извлечённые должность и компанию (вывод JSON):  
  `node .scripts/job-search/run-full-linkedin-teal-flow.cjs --from-text-parse-only path/to/job.txt`
- Без шагов Teal (остановка после шага 5):  
  `... --no-teal`

**Файлы состояния и доказательств (все в `00-Inbox/Job_Search/teal/`):** `full-flow-state.json`, `full-flow-state.md`, `full-flow-evidence.json`, `step-6-evidence.json`, `step-7-evidence.json`, `step-8-evidence.json`, `resume-to-job.json`.
